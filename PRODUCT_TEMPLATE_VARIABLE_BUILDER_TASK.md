# PTB-01. Заменить список переменных продукта на конструктор шаблона

## Цель

Сделать настройку `ProductTemplate.displayTemplate` удобной без знания технических путей переменных. Вместо громоздкого вертикального списка показать компактные русифицированные кнопки-«кирпичики». Наведение или фокус на кнопке показывает подробную информацию, а нажатие вставляет соответствующую конструкцию `{{ variable.path }}` в поле шаблона в позицию курсора.

Ручной ввод и редактирование шаблона должны сохраниться.

## Инструкции для AI-агента

Перед реализацией:

1. Прочитать [`AGENTS.md`](AGENTS.md).
2. Изучить текущие файлы:
   - [`ProductDisplayTemplateEditor.tsx`](client/src/features/create-production-templates/ui/ProductDisplayTemplateEditor.tsx);
   - [`product-display-template.ts`](client/src/features/create-production-templates/api/product-display-template.ts);
   - [`CreateForm.tsx`](client/src/features/create-production-templates/ui/CreateForm.tsx);
   - [`ProductTemplateEditForm.tsx`](client/src/pages/catalogs/ui/ProductTemplateEditForm.tsx);
   - публичный API feature [`index.ts`](client/src/features/create-production-templates/index.ts).
3. Проверить `git status` и не изменять посторонние пользовательские файлы.
4. Выполнить минимальный клиентский патч. Сервер, реестр переменных, DTO, preview API и схема БД не требуют изменений.
5. Не добавлять drag-and-drop: под «кирпичиками» в этой задаче понимаются компактные кнопки с переносом строк.
6. Не менять редактор производственных работ, синтаксис формул и `ProductionOperationEditorFields`. Для формулы требуется другой формат вставки без `{{ }}`, поэтому её перенос на этот UI должен быть отдельной задачей.
7. Не коммитить изменения без отдельной команды пользователя.

## Текущая проблема

В [`ProductDisplayTemplateEditor`](client/src/features/create-production-templates/ui/ProductDisplayTemplateEditor.tsx) переменные выводятся через `Descriptions` по одной на строку:

```text
item.width     : Ширина позиции, мм
item.height    : Высота позиции, мм
material.name  : Название материала
...
```

Недостатки:

- блок занимает много вертикального места;
- пользователю приходится читать технические имена;
- переменную необходимо вручную переписывать в поле вместе с `{{ }}`;
- на узкой форме список визуально конкурирует с тестовыми значениями и preview;
- метаданные реестра используются только как справочник, а не как инструмент ввода.

## Требуемый UX

### Внешний вид

Заменить Card «Доступные переменные» на Card «Конструктор шаблона» с краткой подсказкой:

```text
Нажмите на переменную, чтобы вставить её в шаблон.
```

Внутри расположить кнопки с автоматическим переносом:

```text
[Название продукта] [Ширина позиции, мм] [Высота позиции, мм]
[Толщина позиции, мм] [Количество, шт.] [Материал]
[Цвет] [Патина] [Профиль] [Филёнка] [Лак]
```

Текст кнопки строится из серверных метаданных:

```ts
variable.label + (variable.unit ? `, ${variable.unit}` : '')
```

Не показывать технический `path` основным текстом кнопки.

### Tooltip

При наведении мышью и клавиатурном фокусе показывать tooltip:

```text
Ширина позиции заказа
Вставка: {{ item.width }}
Опциональное значение
```

Tooltip включает:

- `description` из API;
- точную вставляемую конструкцию моноширинным текстом;
- пометку «Опциональное значение», только если `optional === true`.

Расширить клиентский тип `ProductOutputVariable` полем `description: string`; данные уже возвращаются существующим серверным endpoint.

### Вставка переменной

По клику вставлять:

```text
{{ variable.path }}
```

Правила вставки:

1. Если в textarea установлен курсор — вставить токен в позицию курсора.
2. Если выделен фрагмент — заменить выделение токеном.
3. Если поле ранее не было сфокусировано — добавить токен в конец текущего значения.
4. Не добавлять автоматически пробелы, запятые или другие разделители.
5. После вставки вернуть фокус в textarea и поставить курсор сразу после токена.
6. Повторное нажатие той же кнопки допустимо и повторно вставляет переменную.
7. Изменять значение через Ant Design Form API так, чтобы:
   - обновился `Form.useWatch`;
   - запустился существующий debounce-preview;
   - сохранилась валидация поля;
   - форма считалась изменённой.
8. Кнопка должна иметь `htmlType="button"` и не отправлять форму.

Клик по кнопке переводит фокус с textarea, поэтому позицию выделения необходимо сохранять при `select`, `click`, `keyup` и/или перед потерей фокуса. Не полагаться только на `document.activeElement` в момент клика.

### Состояния

- Во время загрузки оставить существующий `Spin` или показать skeleton внутри Card.
- При ошибке сохранить существующий Alert «Не удалось загрузить доступные переменные».
- При пустом массиве показать нейтральный текст «Нет доступных переменных».
- Ошибка загрузки конструктора не должна блокировать ручной ввод, сохранение или preview шаблона.
- Длинные русские подписи должны переноситься внутри кнопки или занимать необходимую ширину без горизонтального overflow формы.

### Доступность

- Использовать настоящие элементы `Button`, а не кликабельные `div`/`Tag`.
- Все действия доступны с клавиатуры через Tab и Enter/Space.
- Tooltip открывается как при hover, так и при focus.
- Добавить понятный `aria-label`, например:

```text
Вставить переменную «Ширина позиции»
```

- Не кодировать смысл только цветом.
- Сохранять видимый focus indicator Ant Design.

## Архитектура и размещение

На этом этапе конструктор имеет одного подтверждённого потребителя — `ProductDisplayTemplateEditor`. Следуя KISS и FSD, оставить реализацию внутри:

```text
client/src/features/create-production-templates/ui/
```

Допустимо создать локальный компонент с предметным именем, например:

```text
ProductTemplateVariableBuilder.tsx
```

Предлагаемый props-контракт:

```ts
type Props = {
  variables: ProductOutputVariable[];
  loading: boolean;
  error?: unknown;
  onInsert: (variable: ProductOutputVariable) => void;
};
```

Логику позиции курсора можно оставить в `ProductDisplayTemplateEditor`, потому что он владеет textarea и Ant Design Form. Компонент кнопок отвечает только за представление метаданных и событие выбора.

Не переносить компонент в `shared/ui` «на будущее». Если позже будет принято решение применить его к шаблону названия работы, сначала определить разные стратегии форматирования:

- продуктовый/строковый шаблон: `{{ path }}`;
- арифметическая формула: `path`;
- шаблон названия работы: `{{ path }}`.

После появления второго реального потребителя можно извлечь нейтральный UI-компонент с передаваемой стратегией `formatToken`.

## Технические ограничения

- Не менять значение `variable.path` и не локализовать его внутри сохраняемого шаблона.
- Русифицируется только подпись кнопки; сервер продолжает получать исходный токен `{{ item.width }}`.
- Не парсить и не перестраивать уже введённый шаблон.
- Не запрещать пользователю вручную вводить текст между переменными.
- Не добавлять автоматическое удаление, перестановку или визуальное превращение уже вставленного текста в отдельные DOM-токены внутри textarea.
- Не использовать `contenteditable`: существующий `Input.TextArea` остаётся источником значения формы.
- Не добавлять новые зависимости.
- Не менять debounce и серверный механизм preview.

## Тестирование

Добавить отдельный тест рядом с редактором или расширить существующий тест формы создания продукта.

Обязательные сценарии:

1. После загрузки вместо технического списка показаны русские кнопки.
2. Tooltip содержит `description` и `{{ path }}`.
3. Клик при пустом поле вставляет токен.
4. Клик вставляет токен в середину существующего текста.
5. Клик заменяет выделенный фрагмент.
6. После вставки курсор находится после токена и textarea снова сфокусирована.
7. Повторный клик вставляет второй токен.
8. Кнопка не вызывает submit формы.
9. Значение попадает в Form и приводит к вызову существующего preview после debounce.
10. Loading, error и пустой список отображаются корректно.
11. Ручной ввод продолжает работать.
12. В create и edit используется один и тот же обновлённый `ProductDisplayTemplateEditor` без дублирования конструктора.

При тестировании позиции курсора учитывать ограничения jsdom: явно вызывать `focus()` и `setSelectionRange()` перед событием клика.

## Критерии приёмки

- Вертикальный `Descriptions` со списком переменных удалён из продуктового редактора.
- Пользователь видит компактные русифицированные кнопки с переносом строк.
- Tooltip показывает описание, технический токен и optional-пометку.
- Клик вставляет `{{ path }}` в ожидаемую позицию, поддерживает замену выделения и возвращает фокус.
- Вставка запускает существующую валидацию и preview.
- Создание и редактирование продукта используют одинаковый конструктор.
- Ручной ввод, серверный preview и сохранение шаблона работают как раньше.
- Серверные файлы и редактор работ не изменены.
- Клиентские тесты, lint, FSD-проверка и production build проходят.

## Вне объёма

- drag-and-drop переменных;
- rich-text или визуальный `contenteditable`-редактор;
- конструктор математической формулы работы;
- изменение редактора производственных работ;
- серверные изменения реестра;
- поиск и фильтрация переменных;
- категории и группировка переменных;
- форматирование значений;
- условные выражения;
- изменение тестовых характеристик или preview-результата.
